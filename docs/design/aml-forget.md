# §10.4 遗忘传播 · 设计正本

> 方案出处：`docs/plans/智能体记忆图书馆实施方案.md` §10.4（L1022–1048）。
> 现状判定：差距表 `docs/design/memory-library-gap.md` §10.4 = ❌（`forget` 只做单条软归档，无派生传播、无凭证、无按主题/全删两种操作）。
> 本文是**边界裁决**，不是待办清单：它先回答「哪些面本插件真的拥有、哪些不拥有」，再谈实现。不先做这一步，实现出来的传播范围一定比方案的九处窄，而窄的地方不会自己报错。

## 1 方案要什么

三种操作（忘记一条 / 忘记一个主题 / 删除全部个人记忆）· 九处传播面 · 最小化删除凭证（不含被删内容）· 结果反馈（不能只返回「已经忘记」）。

## 2 九处传播面 × 本插件的真实载体

**判据**：一个面只有在**本插件写下的数据里**出现，才需要传播。不拥有却声称「已传播」是同一种谎话的两面——所以下面「不拥有」的三行与「有」的四行同等重要。

| 方案的面 | 本插件的真实载体 | 拥有? | 传播动作 |
|---|---|---|---|
| 原始来源 | 宿主会话事件日志（`compaction-sink` 只写入条目，不持有原文） | **否** | 不传播。反馈里**点名**「原文在宿主会话日志，本插件无删除权」 |
| 提炼出的事实 | `entries` 表中 `kind` 非 summary 的条目 | 是 | 条目本体 |
| 自动生成的摘要 | `entries` 表中 `kind=summary`，`archiveRef` 指回原料 id | 是 | 沿 `archiveRef` **双向**传播：删原料要处理引用它的概要；删概要要决定原料去留（默认不动——原料是更原始的事实） |
| 用户画像 | 条目（`memType=profile` / `subject=master`）+ `entities` 表 | **部分** | 条目侧照常传播；实体档**没有 `entry → entity` 边**（§4.3 已知缺口）⇒ 只能按名称/别名命中做**推断式**关联，结果必须标「推断」，不得当作用户授权的确定命中 |
| 知识图谱关联节点 | `relations` 表（`from` / `to`） | 是 | **退役**指向它的边（写 `validTo`），不删记录——「它曾经成立」与「它从没存在过」是两件事 |
| 全文索引 | 无独立索引：正文与「索引」是同一份数据 | **N/A** | 删正文即删索引，不必另做 |
| 向量索引 | 定调不做（主人 2026-10-13） | **N/A** | — |
| 缓存 | 侧车 `memory-access-trace.jsonl`：`{atMs, ids[]}` | 是但**无内容** | **不删**。它只存随机 id 与时刻，不含标题/正文/来源——删了只会毁掉用量归因而不减少任何暴露面。这一点必须写进反馈，否则「传播」会变成「把所有提到过它的地方都删掉」的表演 |
| 备份 | git 历史 / 文件系统快照 | **否** | 不传播。反馈里点名「备份过期策略由仓库与快照层决定，本插件不持有」 |

## 3 三种操作的实现边界

| 操作 | 选择器 | 危险度 | 约束 |
|---|---|---|---|
| 忘记一条 | `id` / `ids[]` / `tier`（既有三选择器） | 低 | 保持现有缺省行为**逐位不变**（软归档） |
| 忘记一个主题 | `topic`（标签 / 概念 id / `memType` / `space` 任一或组合） | 中 | 先 `dryRun` 出清单与计数；命中数超过 `max`（缺省 100 / 上限 500）拒执行并报实际命中数 |
| 删除全部个人记忆 | `scope` 内全部 | **高** | 必须 `confirm: '<scope>'` 逐字匹配；且**执行前必须经 §1.5 请示**（删数据不可逆）——工具只提供能力，不代替授权 |

## 4 凭证

`memory-forget-certificates.jsonl`（侧车，全局追加）。

**最小化判据（可证伪）**：凭证**任何一行都不得包含被删条目的标题或正文片段**。它记的是「处理过什么面、多少个、什么时候、按什么理由」，不是「删了什么内容」。可核法：拿被删条目的 title/body 去 grep 凭证文件，命中即违反。

```ts
/** 一条删除凭证。⚠ 字段是白名单：新增字段前先问「它会不会把内容带回来」。 */
export interface ForgetCertificate {
  certId: string
  at: string
  mode: 'entry' | 'topic' | 'all'
  scope: string
  /** 逐面结果。空的 surfaces 数组不是「没有传播面」，是「没跑传播」——两者必须可区分。 */
  surfaces: Array<{ surface: string; action: string; count: number }>
  /** 命中条目的 id 列表（随机 uuid，无内容）。不存标题/正文/来源。 */
  ids: string[]
  reason?: string
  reasonType: ArchiveReasonType
  /** 未覆盖的面与原因——方案九处里本插件不拥有的那些。必填，它是最容易被省掉的一格。 */
  unowned: Array<{ surface: string; why: string }>
}
```

## 5 结果反馈的形状

不能只返回「已经忘记」。反馈必须同时给四样：**逐面计数**（surface / action / count）· **总量** · **未覆盖面及其原因** · **凭证 id**（可回查）。缺少「未覆盖面」那一格的反馈会让人以为九处都处理了。

## 6 不做什么

- **不做硬删除的缺省**：`purge: true` 显式开启才真删，缺省仍是软归档（`archived: true`）。理由：软归档可回滚，而删错的代价不可逆。
- **不做级联合并**：删一条记忆不自动删除与它内容相同的另一条——那是去重问题，不是遗忘问题。
- **不猜画像关联**：实体档的推断式命中只在反馈里**列出候选**，不自动改档（改档要另一次显式操作）。
- **不碰宿主会话日志**：原文的最小化由宿主层负责，本插件只报坐标。

## 7 判据（实现时并入 `semantic.md` A 表）

- **F1** 缺省关：不给 `mode` 时，`forget` 的行为与 v0.35.1 **逐位相同**（软归档 + 不写凭证）。
- **F2** 传播面完整：删除一条被概要引用、且有关系边的条目后，`surfaces` 恰好含条目本体 / 派生链 / 关系边三项，且关系边的 `validTo` 已写、记录未删。
- **F3** 凭证最小化：凭证文件里 grep 不到被删条目的标题与正文片段（反向：grep 得到即为红）。
- **F4** 未覆盖面必报：反馈里 `unowned` 非空且点名宿主日志与备份层。
- **F5** 主题操作：`dryRun` 与实跑的命中集合一致；超 `max` 拒执行且报实际命中数。
- **F6** 全删护栏：`confirm` 不逐字匹配 scope ⇒ 拒；`purge` 未显式给 ⇒ 只归档。
